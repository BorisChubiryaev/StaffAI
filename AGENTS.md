# AGENTS.md — инструкции для ИИ-агентов, работающих с репозиторием StaffAI

Этот файл читают все ИИ-ассистенты (Claude Code — через `CLAUDE.md`, Codex, Cursor, GigaCode и др.). Держите его коротким:
подробности — по ссылкам.

## Проект в пяти строках

StaffAI — внутренний веб-сервис банка для заказа внешних ИТ-специалистов. Заказчик описывает потребность в диалоге
с AI-агентом (GigaChat); агент уточняет и структурирует её, детерминированная логика проверяет по договорам (КАП)
и справочникам, сотрудник штаба (исполнитель) верифицирует карточку, выбирает подрядчика и отправляет сгенерированный
проект спецификации на согласование; на выходе — конфигурационный пакет для ЗНР в ЛК и пакет для трекера.
Фаза: **старт (Ф0)**, кода продукта ещё нет; есть демо-прототип. Подробно: `docs/onboarding.md`.

## Как работать (SDD)

1. Любая фича — через спецификацию: `specs/NNN-name/spec.md` → `plan.md` → `tasks.md` → код. Процесс: `docs/sdd-process.md`.
2. Не пишите код фичи без спецификации в статусе `Approved` и утверждённого плана (исключения: багфиксы, рефакторинг
   без изменения поведения, chores).
3. Берите одну задачу из `tasks.md`; не выходите за её рамки. Тест — до реализации.
4. Требования берите из источников по иерархии `docs/sources/README.md`: **ТЗ v3 > схемы > ТЗ v2/Замечания > прототип**.
   Известные расхождения (Р-1…Р-12) уже разобраны там же.
5. **Не додумывайте.** Неясность → `[NEEDS CLARIFICATION: …]` в спецификации + строка в `docs/open-questions.md`;
   сообщите человеку. Пометки АР-/ТУ- в ТЗ — неподтверждённые сведения, не реализуйте их как факт.
6. Меняете поведение → в том же PR обновите спецификацию, а также глоссарий / события / модель данных / трассировку,
   если они затронуты.

## Неизменные правила продукта (кратко; полностью — конституция)

- Заказчик **не вводит и не видит** договор, ставки, CI, бюджетные коды, этапы спецификации, служебные данные AI — проверяется на уровне API.
- Решения о подрядчике, бюджете, отправке на согласование принимает **человек**. AI только рекомендует.
- **LLM не управляет системой:** статусы, доступ, расчёты, валидация, рассылки — детерминированный код.
- Модель **не генерирует** договоры, ставки, CI, бюджеты: только из КАП/справочников, иначе «не найдено».
  У каждого AI-вывода — `confidence`, `origin` (user/reference/assumption) и источник.
- Каждое значимое действие — событие журнала; исходный ввод неизменяем; изменения — новые версии.
- Внешние системы — только через адаптеры `mock` / `read_only` / `read_write`; сбой зависимости = деградация, не отказ.

## Данные и безопасность

- В репозиторий, фикстуры, тесты, логи и промпты внешних ИИ-ассистентов — **только синтетические или обезличенные данные**.
  Никаких реальных договоров, ставок, ФИО, номеров ЗНР.
- Секреты и учётные данные интеграций не коммитятся (`.env*` в `.gitignore`; шаблон переменных без значений — `.env.example`, когда появится код).
- Реальные данные обрабатывает только GigaChat в контуре банка.

## Соглашения

- **Язык:** документация, спецификации, UI-тексты — русский; код, идентификаторы, коммиты-типы, API, БД — английский.
  Имена доменных сущностей — строго по колонке «В коде» в `docs/product/glossary.md`.
- **Статусы заявки** — только коды из `docs/domain/request-lifecycle.md` (не из прототипа и не из ТЗ v2).
- **Коммиты:** Conventional Commits со ссылкой на спецификацию — `feat(001): …`, `docs(spec-021): …`, `chore: …`.
- **Ветки:** `NNN-short-name`.
- **Стек продукта не выбран** (ОВ-01). Не вводите новые технологии без ADR (`docs/architecture/adr/`).

## Прототип

`prototype/` — Next.js 14 + TypeScript + Tailwind, всё на моках (`prototype/lib/demo-store.tsx`).
Запуск: `cd prototype && npm ci && npm run dev`; сборка: `npm run build`.
Он иллюстрирует UX, но реализует часть target-state (автосоздание Epic, ЗНР через ЛК, голос) и свою статусную модель.
Не переносите его решения в продукт без сверки со спецификацией.
