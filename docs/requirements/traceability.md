# Трассировка требований

Каждое требование ТЗ v3 должно быть покрыто хотя бы одной спецификацией. Колонка «Спецификация» — плановое покрытие
из [реестра](../../specs/README.md#реестр-спецификаций); статус берётся из `spec.md`. Команда `/sdd.analyze` сверяет этот файл
со спецификациями и сообщает о непокрытых требованиях.

**Правило обновления:** создали/переименовали спецификацию или перераспределили требования — обновите таблицу в том же PR.

## Правила работы AI

| ID | Правило | Спецификация |
|---|---|---|
| ПР-1 | Факты / справочные данные / предположения разделены | 010, 011, 016 |
| ПР-2 | Уверенность для каждого вывода; низкая — на проверку | 010, 011, 030 |
| ПР-3 | Запрет генерации договоров, ставок, CI, бюджетов | 011, 016, 032, 034 |
| ПР-4 | Журналирование AI-выводов, подтверждений и правок | 002, 010, 030 |
| ПР-5 | LLM не используется для статусов, доступа, расчётов, валидации, рассылок | 001, 003, 021, 035 (+ ADR-0002) |
