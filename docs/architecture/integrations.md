# Интеграции

> Источник: ТЗ v3 §7. Режимы ФТ-6.4: `mock` (заглушка) / `read_only` / `read_write`. Режим каждой интеграции —
> конфигурация окружения, не код.

## Принципы

1. Все ИВ — через слой адаптеров; замена внешней системы не затрагивает бизнес-логику.
2. Недоступность внешней системы не останавливает процесс: отложенная задача синхронизации, ограниченный режим
   для пользователя, данные сохраняются локально.
3. Система не является источником истины для справочных данных; AI не подменяет справочники.
4. Учётные данные интеграций изолированы (НФТ «Безопасность»); в репозиторий не попадают.

## Резервные сценарии (критический путь)

| Система | Если не готова / недоступна |
|---|---|
| GigaChat | Черновик сохраняется; шаблонный путь; ручная обработка штабом; повтор вызова из очереди |
| КАП | Выгрузка / заглушка; проверки помечаются «не выполнено — нет данных», а не «пройдено»; флаг для исполнителя |
| ЛК | Исполнитель скачивает конфигурационный пакет и загружает вручную; статус ЗНР — ручная отметка |
| Справочники | Последняя синхронизированная копия; сопоставление помечается `unavailable`, задача ручной проверки |
| Трекер | Пакет параметров (в MVP это и есть основной режим) |

## Перспективные ИВ (вне Этапа 1)

Библиотека знаний (Jira/Confluence: рамочные договоры, спецификации), Пульс ЕК, ServiceManager, FinAI (инициативы),
COST IT, целевая АС (оплата/НМА). Требование к архитектуре: подключаемы через адаптеры без изменения ядра.
