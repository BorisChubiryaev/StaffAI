# Глоссарий и единый язык (ubiquitous language)

Документация пишется на русском, **код — на английском**. Колонка «В коде» — обязательное имя сущности/понятия в коде,
API, БД и событиях. Не придумывайте синонимы: если нужного термина нет — добавьте его сюда в том же PR.

## Бизнес-термины

| Термин | В коде | Значение |
|---|---|---|
| StaffAI, Система | `staffai` | Сервис автоматизации заказа внешних ИТ-специалистов |
| Заказчик | `Customer` (роль `customer`) | Владелец продукта / руководитель, заказывающий внешних специалистов. Владелец потребности |
| Штаб | `Staff` | Операционное подразделение, обрабатывающее заказы |
| Исполнитель, сотрудник штаба | `Executor` (роль `staff`) | Сотрудник штаба, обрабатывающий заявку и принимающий решения |
| Администратор | роль `admin` | Управляет шаблонами, справочниками, доступами; смотрит журналы |
| Подрядчик | `Contractor` | Внешняя компания, поставляющая специалистов по рамочному договору. В системе не работает, получает проект спецификации по почте |
| Заявка | `Request` | Единая сущность жизненного цикла одного запроса: статусы, история, артефакты. Идентификатор — уникальный номер (формат см. ОВ-10), не название |
| Обращение | `Inquiry` | Входящее сообщение в диалоге. Может стать заявкой или быть вопросом по процессу |
| Канал обращения | `channel` | Атрибут источника обращения (`web`; в будущем — `email` и др., АР-01) |
| Сессия диалога | `DialogSession` | Переписка заказчика с AI-агентом в рамках заявки; восстанавливается при разрыве |
| Исходный ввод | `RawInput` | Неизменённый текст/файлы заказчика. Хранится отдельно от обработанных данных |
| Карточка запроса | `RequestCard` | Структурированное представление потребности, сформированное агентом и подтверждаемое заказчиком |
| Позиция (роль заявки) | `RequestRole` | Строка состава: роль × грейд × количество × сроки × требования |
| Роль | `Role` | Роль из справочника, связанная с договорными тарифами (не «разработчик вообще») |
| Грейд | `Grade` | Уровень: junior / middle / senior (+ значения справочника) |
| Календаризация | `Calendarization` | Даты старта/окончания по позициям; команда может подключаться поэтапно |
| Формат работы | `WorkFormat` | Офис / удалённо / гибрид и пр. |
| Пакет документов | `DocumentPackage` | Комплект файлов, приложенных заказчиком к заявке |
| Шаблон запроса | `RequestTemplate` | Заготовка заявки: системная, подразделения или личная (`scope`) |
| Уточнение | `Clarification` | Вопрос агента/штаба заказчику и ответ; треды уточнений — `ClarificationThread` |
| Противоречие | `Contradiction` | Несовместимость данных (грейд vs опыт, роль vs стек). Подсвечивается, не блокирует |
| Отчёт о проверке | `ValidationReport` | Результат проверки и валидации: правила, ошибки, флаги |
| Флаг проверки | `ValidationFlag` | `ok` / `budget_exceeded` / `near_limit` / `contract_extension_required` |
| Контрольный перечень | `ValidationRuleSet` | Настраиваемый состав правил проверки (формирует штаб, прил. Г) |
| Цикл пояснений | `ExplanationLoop` | Шаг 4а: ошибки → понятные пояснения → исправление; с лимитом итераций и эскалацией |
| База знаний процесса | `ProcessKnowledgeBase` | Ответы на вопросы о порядке оформления (наполняет штаб, прил. В) |
| Вариант подрядчика | `ContractorOption` | Рекомендация: покрытие ролей, тарифы, остаток бюджета, срок договора, рейтинг |
| Рамочный договор | `FrameworkContract` | Договор с подрядчиком: роли, тарифы, лимит, срок |
| Тариф, ставка | `Rate` | Ставка по роли/грейду из договора. Только из КАП, никогда не генерируется |
| Инициатива | `Initiative` | Сущность платформы инициатив (FinAI); привязка опциональна |
| Проект спецификации | `SpecificationDraft` | Черновик спецификации к рамочному договору; версионируется (`SpecificationVersion`) |
| Решение исполнителя | `ExecutorDecision` | `send` / `return` / `adjust` |
| Маршрут согласования | `ApprovalRoute` | Участники рассылки (подрядчик, исполнитель, заказчик) и статусы их ответов |
| ЗНР | `ResourceRequest` (`znr` в интеграции) | Заявка на ресурс, оформляется в ЛК |
| Конфигурационный пакет | `LkConfigPackage` | JSON для создания черновика ЗНР в ЛК |
| Пакет параметров для трекера | `TrackerPackage` | Параметры Epic + Story для ручного создания задач |
| Артефакт | `Artifact` | Любой сгенерированный документ/пакет с версией и статусом |
| AI-вывод | `AiInference` | Результат вызова модели: значения, уверенность, источник, предположения; журналируется |
| Уверенность | `confidence` | 0..1 для каждого AI-вывода; ниже порога — на проверку исполнителю |
| Фрагмент-источник | `sourceFragment` | Цитата исходного ввода, из которой получен вывод |
| Сопоставление со справочником | `ReferenceMatch` | Связь «введённое значение → элемент справочника» с уверенностью |
| Событие журнала | `DomainEvent` / `EventLog` | Факт значимого действия: id, заявка, актор, время, payload, корреляция, источник |
| Human-in-the-loop | — | Принцип: значимые решения принимает человек |

## Системы и аббревиатуры

| Термин | В коде (адаптер) | Значение |
|---|---|---|
| ЛК | `lk` | Личный кабинет заказчика ИТ-ресурсов — внешняя система, где оформляется ЗНР |
| КАП | `kap` | Хранилище данных о рамочных договорах, ролях, тарифах, бюджете. Источник истины по договорам |
| МИП | — | Название хранилища данных в ТЗ v2; вероятно, то же, что КАП (ОВ-05) |
| ЕСУП | — | Downstream-система исполнения; прямой интеграции нет, только через ЛК |
| СУДИР | `sudir` | Корпоративная система аутентификации (SSO) |
| GigaChat | `gigachat` | LLM, ядро AI-агента. Единственная разрешённая модель для реальных данных |
| СберТрек / Jira | `tracker` | Трекер задач (идёт миграция Jira → СберТрек, ТУ-07) |
| FinAI | `finai` | Платформа управления инициативами; кандидат на размещение (АР-02) |
| COST IT | — | Агент оценки стоимости инициатив; потенциальная связка «оценка → заказ» |
| ЭДО | — | Электронный документооборот (подпись ЗНР штабом в ЛК) |
| CI | `ciCode` | Код автоматизированной системы/подсистемы/модуля, над которым ведутся работы |
| НМА | — | Нематериальные активы (учёт — вне периметра) |
| ЕК | — | Единый каталог продуктов банка (карточка продукта — Видение) |
| Пульс ЕК, ServiceManager | — | Перспективные интеграции |
| ИВ | — | Интеграционное взаимодействие (ИВ-1…ИВ-7 в ТЗ) |
| ПСИ | — | Приёмо-сдаточные испытания |
| ПРОМ | — | Промышленный контур эксплуатации |
| ИБ | — | Информационная безопасность |
| B2C / B2E | — | Блок банка / внутренние пользователи (employees) |
| SA | — | Системный аналитик |
| КР | — | Команда разработки |
