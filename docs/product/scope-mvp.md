# Границы MVP (Этап 1)

> Источник: [ТЗ v3](../sources/01-tz-v3-mvp.md) §2.3, §5.3, §6, §10, §11. Формальное утверждение границ — **ТУ-11 / задача Ф0-0.1**:
> до утверждения документ описывает согласованную позицию ТЗ v3, а не обязательство.

## Что входит

Сквозной путь одной заявки через веб-сервис:

1. **Вход** через СУДИР; диалог с AI-агентом: свободный текст, файлы (TXT, MD, DOCX, PDF, XLSX), шаблоны запросов.
2. **Обработка обращения**: извлечение параметров (роли, грейды, количество, сроки и календаризация, стек, формат работы,
   контекст), нормализация по справочникам; вопрос по процессу → ответ по базе знаний без создания заявки.
3. **Уточняющий диалог**: только содержательные вопросы, ≤3–5 за итерацию; противоречия подсвечиваются, не блокируют.
4. **Проверка и валидация**: базовые проверки + сверка с договорами КАП → отчёт с флагами.
   4а. **Цикл пояснений**: ошибки → LLM объясняет простым языком → до устранения, с лимитом итераций и эскалацией.
5. **Карточка запроса** → подтверждение заказчиком → очередь штаба.
6. **Рабочее место исполнителя**: верификация выводов AI, чат с заказчиком, выбор подрядчика из рекомендаций,
   привязка к инициативе (опционально), ручная правка любых AI-данных с фиксацией автора.
7. **Проект спецификации**: шаблон + карточка + договорные данные; версионирование; экспорт DOCX/PDF + JSON.
8. **Решение исполнителя**: отправить / вернуть / скорректировать.
9. **Рассылка на согласование** (подрядчику по почте, исполнителю, заказчику) с фиксацией статусов.
10. **Downstream-пакеты**: конфигурационный пакет (JSON) для ЛК (черновик ЗНР) и пакет параметров для трекера.

Сквозное: статусная модель, ролевой доступ, журнал событий, уведомления (интерфейс + почта), адаптеры интеграций
с режимами mock / read-only / read-write, асинхронная обработка, деградация без остановки процесса.

Плюс для заказчика: «Мои заявки» (фильтры, история), повтор завершённой заявки, личные шаблоны.
Плюс для администратора: шаблоны, справочники, доступы, журналы.

## Что НЕ входит

| Не входит | Где будет | Источник |
|---|---|---|
| Голосовой ввод | Вне Этапа 1 | ТЗ §5.2 |
| Приём обращений по почте | Решение АР-01 | ТЗ §5.1 |
| Автосоздание Epic/Story в СберТрек/Jira | Фаза 2 | ИВ-5 |
| Создание ЗНР через API ЛК | Целевой контур | ИВ-4 |
| Согласование спецификации в действующих системах | Существующие процессы; фиксируется только статус | ТЗ §2.3 |
| Этап выполнения работ, проверка артефактов выполнения, запуск оплаты | Этап 2 | ТЗ §2.3 |
| Оплата, учёт НМА | Целевая АС при миграции | ТЗ §2.3 |
| Интеграции: библиотека знаний, Пульс ЕК, ServiceManager, FinAI (API), COST IT | Перспектива; архитектура готова через адаптеры | ТЗ §7.3 |
| Автономный выбор подрядчика, автоутверждение бюджета, автоотправка, подписание | Только отдельным изменением требований по метрикам | ТЗ §4 |
| Мультиагентная production-архитектура, предиктивный стаффинг, продвинутая аналитика | Вне MVP | ts-v2 §23.2 |

## Приёмочные сценарии

Каждая спецификация фичи ссылается на сценарии, которые она закрывает (см. [трассировку](../requirements/traceability.md)).

| # | Сценарий | Критерий |
|---|---|---|
| ПС-1 | Заявка через веб-сервис: диалог → карточка → подтверждение → обработка исполнителем → выбор подрядчика → проект спецификации → решение → рассылка | Пройден без ручного переноса данных; статусы и события зафиксированы |
| ПС-2 | Заявка с приложенными документами, содержащими ошибки | Ошибки найдены автоматически, пояснения в диалоге, после исправления — полный путь |
| ПС-3 | Вопрос по процессу в диалоге | Содержательный ответ AI без создания заявки |
| ПС-4 | Контроль зоны заказчика | Заказчик нигде не вводит договорные/бюджетные атрибуты; данные не вводятся повторно |
| ПС-5 | Конфигурационный пакет для ЛК | Соответствует согласованной структуре, принят тестовым контуром ЛК |
| ПС-6 | Пакет параметров для трекера | Исполнитель создаёт задачи по пакету без обращения к исходной переписке |
| ПС-7 | Аудит | По журналу восстановлена полная история произвольной заявки |
| ПС-8 | Нагрузочное испытание | НФТ подтверждены ([nfr.md](../architecture/nfr.md)) |

Порядок приёмки: стендовые испытания ПС-1…ПС-8 → устранение замечаний → ПСИ с проверкой ИБ → пилот на ограниченной
группе → анализ метрик → решение о промышленной эксплуатации.

## Метрики

Собираются автоматически с первого дня эксплуатации (а значит, события под них закладываются с Ф1 — см. [события](../domain/events.md)).

- **Процессные:** время до структурированного запроса; время проверки штабом; время до проекта спецификации; полный цикл;
  доля успешно завершённых заявок.
- **Качество AI:** точность извлечения; число уточняющих итераций; доля ручных корректировок; доля выводов с низкой
  уверенностью; инциденты недостоверной генерации.
- **Использование:** распределение по источникам обращения; повторное использование шаблонов; активные заказчики.
