# Роли, зоны ответственности и видимость

> Источник: ТЗ v3 §4, ФТ-1.7, ФТ-6.2; ts-v2 §4, §11.7. RACI-матрица (прил. А) формируется на детальном проектировании —
> ниже рабочая версия из ts-v2 §4.3, адаптированная под v3.

## Роли

| Роль | Код | Делает | Не делает |
|---|---|---|---|
| **Заказчик** | `customer` | Формулирует потребность (диалог, файл, шаблон), отвечает на уточнения, подтверждает карточку, согласует содержательную часть спецификации, может высказать пожелание по подрядчику | Не выбирает договор и подрядчика; не вводит бюджетные коды, CI, ставки; не формирует спецификацию и ЗНР |
| **Исполнитель** (штаб) | `staff` | Ведёт очередь, верифицирует выводы AI, уточняет детали, выбирает подрядчика, правит проект спецификации, решает об отправке на согласование, запускает оформление ЗНР | Не собирает данные с нуля; не переносит данные между системами вручную |
| **Администратор** | `admin` | Шаблоны, справочники, доступы, журналы | — |
| **AI-агент** | актор `ai` | Принимает и структурирует потребность, задаёт вопросы, нормализует, объясняет ошибки, рекомендует, генерирует тексты | Не принимает решений о подрядчике, бюджете, отправке, юридически значимых действиях; не меняет статусы |
| **Система** | актор `system` | Статусы, проверки, рассылки, уведомления, синхронизация | — |

## Доступ к данным (ФТ-6.2)

- Заказчик видит **только свои** заявки.
- Исполнитель — очередь и назначенные ему заявки.
- Администратор — всё.

## Ролевая прозрачность AI (ФТ-1.7, ts-v2 §11.7)

| Слой | Кто видит | Что |
|---|---|---|
| **Бизнес-уровень** | Заказчик | Что система поняла; состав команды; сроки; требования; содержательные вопросы; что будет дальше |
| **Слой проверки** | Исполнитель | Исходный ввод; извлечённые значения с уверенностью и фрагментами-источниками; противоречия и неопределённости; сопоставления со справочниками; предположения; результаты проверок и флаги; рекомендуемые действия |
| **Аудит / отладка** | Администратор | Журналы, ошибки интеграций, технические статусы обработки, audit trail |

**Заказчику никогда не отображаются:** договорные и бюджетные атрибуты, уровень уверенности, источники, внутренние
сопоставления, предположения о подрядчике. Это требование проверяется в API (поля не отдаются), а не только скрывается в UI.

## RACI (рабочая версия)

R — исполняет, A — отвечает за результат, C — консультирует, I — информируется.

| Действие | Заказчик | AI | Исполнитель |
|---|:-:|:-:|:-:|
| Описать потребность | R | C | I |
| Распознать и нормализовать роли | C | R | A |
| Уточнить пробелы | R | R | C |
| Проверить заявку по правилам и КАП | I | C (пояснения) | A (система — R) |
| Подтвердить карточку | A/R | C | I |
| Выбрать договор / подрядчика | C | C | A/R |
| Привязать к инициативе | — | C | A/R |
| Сформировать проект спецификации | I | R | A |
| Решить об отправке на согласование | I | — | A/R |
| Согласовать содержательную часть | A/R | — | R |
| Оформить ЗНР | I | C (пакет) | A/R |
