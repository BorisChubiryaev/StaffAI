# 02. Схема процесса: от точки входа до последнего действия

## Слайд 1. StaffAI — сервис заказа внешних ИТ-специалистов
*Общая картина процесса. Вход по СУДИР*

1. **Веб-сервис** — заказчик начинает диалог, вход по СУДИР.
2. **AI-агент StaffAI** — обработка, уточнение, проверка.
3. **Проект спецификации** сформирован и отправлен на согласование: подрядчику (по электронной почте), исполнителю (штаб), заказчику.
   Финальное решение об отправке на согласование принимает исполнитель.
4. **Оплата** (контроль у сотрудника штаба) — не участвует в разработке / Этап 2.
5. **НМА** — не участвует в разработке.

## Слайд 2. Заказчик говорит — система делает
*Клиентский путь заказчика*

1. Заказчик описывает потребность: свободный текст, файл или шаблон.
2. AI-диалог уточнения: роли, грейды, стек, количество, сроки, формат, контекст.
3. Структурированная карточка запроса показана заказчику.
4. Подтверждение заказчиком. Ветки: «Измени…» → назад к шагу 2; «Всё верно» → шаг 5.
5. Запрос передан штабу, статус «Запрос принят».
6. Ответы на уточнения штаба в том же диалоге (если нужны).
7. Уведомление: заявка оформлена и передана в ЛК.

## Слайд 3. Штаб работает с результатом AI-анализа
*Подготовленная карточка вместо сырого запроса*

1. Карточка в очереди штаба.
2. Проверка карточки: выводы AI, уверенность, флаги (бюджет, срок договора).
3. Уточнение у заказчика: чат в контексте заявки (ветка «нужны детали» из шага 2).
4. Выбор подрядчика из рекомендаций (покрытие ролей, тарифы, остаток бюджета, рейтинг).
5. Привязка к инициативе (опционально, AI подсказывает).
6. Проект спецификации сгенерирован по шаблону.

## Слайд 4. Финальное решение — за исполнителем
*Решение человека и согласование (human-in-the-loop)*

1. Проект спецификации готов к отправке.
2. Решение за человеком (исполнитель, штаб) — «на первое время». Ветки: «отправить» / «вернуть».
3. Рассылка на согласование: подрядчику (по почте), исполнителю, заказчику.
4. Процесс согласования в разных системах — не участвует в разработке.
5. Этап выполнения работ — не участвует в разработке.

## Слайд 5. Последняя миля: оформление без повторного ввода
*Downstream: ЗНР в ЛК, задачи в трекере, ЕСУП*

1. Подтверждённая карточка и выбранный подрядчик.
2. Конфигурация (JSON): роль, грейд, количество, сроки, подрядчик, бюджетные реквизиты.
3. ЛК заказчика ИТ-ресурсов: автосоздание черновика ЗНР.
4. Штаб проверяет, подписывает в ЭДО.
5. ЕСУП (через ЛК, прямой интеграции нет).
6. Пакет для СберТрек / Jira — на первом этапе шаблон для ручного создания; на втором этапе автосоздание Epic и Story.

## Слайд 6. Этапность реализации

| Этап | Содержание | Статус |
|---|---|---|
| Этап 1 (MVP) | Приём и обработка заявки через веб-сервис, проверка и валидация заявки, проект спецификации, решение человека, рассылка на согласование; конфигурация для ЛК; пакет для трекера | В разработку |
| Этап 2 | Проверка артефактов и подготовка запуска оплаты | После реализации Этапа 1 |
| Целевая АС | Оплата (контроль у штаба), НМА; реализуются при миграции | При миграции |
| Перспектива | Библиотека знаний (Jira/Confluence: рамочные договоры, спецификации), Пульс ЕК, ServiceManager | Требует проработки |
