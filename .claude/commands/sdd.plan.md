---

Вход: `$ARGUMENTS` (первое слово — ID спецификации, остальное — технические указания пользователя).

## Предусловия

- `specs/NNN-*/spec.md` в статусе `Approved` (или `Clarified`, если пользователь явно разрешил). Иначе — остановись и
  предложи `/sdd.clarify`.
- Прочитай `.specify/memory/constitution.md`, `AGENTS.md`, `docs/architecture/*` (включая ADR), `docs/domain/*`,
  `docs/ai/agent-rules.md`, планы зависимых спецификаций.
- Технологический стек берётся из принятого ADR (ОВ-01). Если ADR нет — не выбирай стек молча: предложи вариант
  оформить ADR-проект (`.specify/templates/adr-template.md`) и отметь в плане `[NEEDS CLARIFICATION]`.

## Шаги

1. Скопируй `.specify/templates/plan-template.md` → `specs/NNN-*/plan.md`.
2. Заполни технический контекст.
3. **Проверка конституции (до проектирования):** по каждой статье — как план её соблюдает. Нарушение без обоснования —
   стоп: переработай подход или запиши «Обоснованное отклонение» и попроси согласия пользователя.
4. **Исследование** → `research.md`: для каждой неизвестной — Решение / Почему / Отклонённые альтернативы.
5. **Проектирование:**
   - `data-model.md` — сущности фичи, поля, ограничения, версионирование (на основе `docs/domain/data-model.md`).
   - `contracts/` — OpenAPI для API, JSON Schema для событий, AI-контрактов, пакетов ЛК/трекера.
   - Интеграции: режим каждой зависимости и поведение при её недоступности.
   - AI (если есть): промпты (где лежат), схема ответа, eval-набор, порог, обработка невалидного ответа.
   - События и аудит; видимость данных по ролям на сервере.
6. **Стратегия тестирования:** приёмочные из сценариев spec, модульные, контрактные, eval, режимы отказа.
7. **Проверка конституции (после проектирования)** — повтори.
8. Значимые решения (технология, интеграция, дорого отменить) — оформи ADR в `docs/architecture/adr/` со статусом
   «Предложено» и добавь в индекс.
9. Обнови статус spec → `Planned` (после утверждения плана) и `specs/README.md`.

Отчёт: созданные файлы, результат проверки конституции, предложенные ADR, открытые вопросы. Следующий шаг — `/sdd.tasks NNN`.
