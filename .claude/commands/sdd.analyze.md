---
description: Проверить согласованность spec ↔ plan ↔ tasks ↔ код ↔ конституция ↔ трассировка (только чтение)
argument-hint: <NNN> | all
---

Вход: `$ARGUMENTS` — ID спецификации или `all` для всего репозитория. **Ничего не меняй** — только отчёт.

Проверки:

1. **Покрытие:** каждое FR и сценарий spec → есть задачи → есть тесты/код. Требования ТЗ, назначенные спецификации в
   `docs/requirements/traceability.md`, реально отражены в её FR. Для `all` — требования ТЗ без спецификации.
2. **Согласованность:** plan не противоречит spec; задачи не вводят функциональность вне spec; термины соответствуют
   глоссарию; статусы и события — `docs/domain/request-lifecycle.md` и `docs/domain/events.md`.
3. **Конституция:** нарушения статей (особенно II, V, VI, VII, VIII, IX, XI) в spec, plan и коде. Нарушение конституции —
   всегда CRITICAL.
4. **Неясности:** оставшиеся `[NEEDS CLARIFICATION]`, вопросы, которых нет в `docs/open-questions.md`, и закрытые там
   вопросы, не перенесённые в spec.
5. **Источники:** требования, опирающиеся на ts-v2/прототип там, где ТЗ v3 говорит иначе (см. Р-n в `docs/sources/README.md`).
6. **Статусы:** статус в spec.md совпадает с реестром `specs/README.md` и фактическим состоянием задач.

Формат отчёта — таблица: `ID | Серьёзность (CRITICAL/HIGH/MEDIUM/LOW) | Где (файл:строка) | Проблема | Рекомендация`,
затем метрики (покрытие FR, % задач с тестами, число открытых вопросов) и 3–5 рекомендуемых действий по приоритету.
